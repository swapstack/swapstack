Three decoupled layers. Verified by contract tests.

Every mock and live adapter runs against the same reusable Jest contract suites in src/core/contracts/ so behavior stays consistent across vendors.

Presentation & Route Kits
src/app/ · src/features/ · src/components/ui/

Session-gated Expo Router groups and token-driven UI primitives.

Public Auth Flow (auth)

Login, sign-up, password recovery, email verification pending, and guest-to-account upgrade screens.

Authenticated Shell (app)

Automatic session restore, profile editing, guest sign-out data warnings, and account deletion.

Subscription Paywall paywall.tsx

Displays offerings, active entitlements, purchase loading states, and restore purchases.

Core Contracts & Registry
src/core/ · src/lib/providers/

Vendor-free TypeScript interfaces, models, typed errors, and startup validation.

AuthProvider Contract

signIn, signUp, signInWithOAuth, signInAnonymously, linkAccount, updateProfile, deleteAccount.

DataRepository Contract

get, update, and real-time subscribe for user profiles with deterministic listener cleanup.

BillingProvider Contract

getOfferings, purchase, restore, getEntitlements, and onEntitlementsChange.

Swappable Service Adapters
src/core/mocks/ · src/lib/providers/

Plug-and-play implementations resolved dynamically from environment variables.

In-Memory Mocks mock

Default local development and fast CI component testing without network flakiness or external accounts.

Supabase Adapter supabase

Email, OAuth, anonymous sessions, and profiles table sync backed by namespaced expo-secure-store.

RevenueCat Adapter revenuecat

Wraps react-native-purchases v11, mapping offerings, customer info, and cancellation states to BillingError.

Read Quick Start in README Customize Design Tokens (DESIGN.md)

Enable the Supabase Auth & Profile Adapters

Set EXPO_PUBLIC_AUTH_PROVIDER=supabase and EXPO_PUBLIC_DATA_PROVIDER=supabase in your .env file along with your project URL and anon public key. 

EXPO_PUBLIC_AUTH_PROVIDER=supabase
EXPO_PUBLIC_DATA_PROVIDER=supabase
EXPO_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=your-anon-key

# Prebuild scripts enforce STRICT_ENV_VALIDATION=1 automatically:
pnpm run prebuild:production
Full Supabase Setup & SQL Schema Guide (docs/supabase.md)

Enable the RevenueCat Billing Adapter

Set EXPO_PUBLIC_BILLING_PROVIDER=revenuecat and provide your RevenueCat public SDK key. Because native store purchases require StoreKit / Google Play Billing, use an Expo development build (pnpm run ios or pnpm run android). 

EXPO_PUBLIC_BILLING_PROVIDER=revenuecat
EXPO_PUBLIC_REVENUECAT_PUBLIC_SDK_KEY=appl_your_public_sdk_key

# Run a native development build to test store offerings:
pnpm run ios
Full RevenueCat Setup Guide (docs/revenuecat.md)

Implement & Verify a New Provider Adapter

Implement AuthProvider, DataRepository, or BillingProvider, register it in src/lib/providers/registry.ts, and verify compliance with the shared contract test suite. 

import { describeAuthProviderContract } from '@/core/contracts';
import { createAcmeAuthProvider } from '../auth-provider';

// Runs the complete lifecycle contract test suite against your adapter:
describeAuthProviderContract('AcmeAuthProvider', () => createAcmeAuthProvider());

export type WorkoutEntry = {
  id: string;
  userId: string;
  title: string;
  durationMinutes: number;
  completedAt: string;
};

export type WorkoutStats = {
  totalWorkouts: number;
  currentStreakDays: number;
  totalMinutes: number;
};

export type WorkoutRepository = {
  readonly mode: 'mock' | 'live';
  list: (userId: string) => Promise<WorkoutEntry[]>;
  log: (userId: string, input: { title: string; durationMinutes: number }) => Promise<WorkoutEntry>;
  remove: (userId: string, workoutId: string) => Promise<void>;
  getStats: (userId: string) => Promise<WorkoutStats>;
};
AI Build Prompt — Pulse 
Build the "Pulse" Habit & Workout Tracker app in this Swapstack project following `AGENTS.md`:

1. Create `src/core/workouts.ts` with `WorkoutEntry`, `WorkoutStats`, and `WorkoutRepository` types (use `type` definitions, no vendor imports).
2. Create `src/core/mocks/mock-workout-repository.ts` implementing `WorkoutRepository` in memory with deterministic streak calculation and a `reset()` helper for tests.
3. Create `src/core/contracts/workout-repository.contract.ts` (`describeWorkoutRepositoryContract`) and run it in `src/core/__tests__/workout-repository.test.ts`.
4. Register `workouts` in `src/lib/providers/registry.ts` and expose `serviceProviders.workouts` in `src/lib/services/index.ts`.
5. Update `src/app/(app)/index.tsx` so users (including anonymous guests) can log workouts, view their workout history, and see a "Pro Streak Analytics" card that checks `serviceProviders.billing.getEntitlements()` for an active `pro` entitlement (linking to `/paywall` when locked).
6. Add React Native Testing Library tests in `src/app/(app)/__tests__/index.test.tsx` and run `pnpm run lint`, `pnpm run type-check`, and `pnpm test`.
